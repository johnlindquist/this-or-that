# Current this-or-that contract

1. A collection contains many candidates. The current sprint collection has 22: two incumbents and 20 independent exploration drafts.
2. The comparison surface shows exactly two current candidates at equal size. Left/Right chooses one; Skip, Like both and Hate both record non-winning outcomes. Each advances after persistence. Typing a note never votes. Embedded candidates and gallery previews accept interaction immediately, without an Explore gate. Escape returns focus from a demo to the parent controls without disabling the iframe; demo interactions never create preference records.
3. Candidate-specific notes follow the candidate across matchups. Comparison notes belong to the recorded choice. Local draft state is distinct from server acknowledgment.
4. A merge-style schedule organizes comparisons. Final standings use score = Elo + 16 × (likes − hates). Skip changes no score. Shared feedback changes both equally and does not fabricate a head-to-head win/loss. Another pass retains notes and prior comparison evidence.
5. No final winner is asserted before completion, for a tied top score, or for unassessed candidates. Equal assessed scores share competition ranks; skipped-only candidates have no rank. Progress and completed ties remain exportable. Winner source is available only for a unique assessed leader. Exports retain outcome counts, notes, comparisons, identity and provenance.
6. Candidate scratch assignment/reorder/reset/undo state is not preference evidence. The shared sprint helper uses the existing movement reducer and synthetic fixture. Each generated candidate owns one standalone HTML file.
7. Session actions target an exact UUID, expected revision and current pair identity. Identical retries are idempotent. Stale or changed-payload requests are rejected rather than rebased.
8. Agents can inspect/export human sessions but only create/mutate rehearsal sessions through the supported API. Local actor labels are conventions, not authentication.
9. Saved sessions live under `.tournament-data` by default, separate from earlier fixed-A/B records. Serialized atomic JSON persistence and a single-process lock protect acknowledged choices. Preserve records during recovery.
10. The approved Things Folio shell is the live ranking app, with light/dark/system appearance, generous paired previews, friendly spacing and passive side emphasis. Candidate UIs remain exploration drafts, not production-certified products. Default e2e coverage targets current Folio and chrome-review behavior; retained fixed-A/B tests and their historical counts do not certify this app.

See [AGENT_API](AGENT_API.md) for discovery, schemas, operations, limits and recovery, and [the README](../README.md#checks-and-test-scope) for standalone commands and test scopes. `bun run start` runs `tournament/server.ts`. The earlier `server/` and unused `web/` SPA entrypoints remain historical source; `shared/`, `web/widgets/` and the incumbent stylesheets remain required by the live demos.
